TextScript

The no-programming tier. A TextScript is a plain .txt file of labelled blocks, one command per line — no Java, no classes, no compiling. This is why the script folders of a 2006 install are full of files written by people who never wrote a line of code, and all eleven scripts that survive from that era run here untouched.

Quick start

Save this as scripts/Textscript/Picker.txt and type /start Picker:

[main]
autologin(true)
display(@ran@Anything Picker)
goto([pickup])

[pickup]
pickupitembyid(441)
wait(350)
goto([pickup])

That is a complete, real script — it picks up every item with id 441 it can see, forever, until /stop.

The rules

  • [label] is a jump target, not a scope. Execution starts at line 1 (not at [main]) and falls off the bottom of one block into the next — several surviving scripts depend on exactly that.
  • goto([label]) jumps. The dozens of gotoif… commands jump only when their condition holds — that is the whole control flow.
  • | starts a comment.
  • #name# is a variable you set with setvar; $name$ is a value read off the game — $fatigue$, $hits$, $xcoord$, $mining$, any skill by name.
  • Items are addressed by item id, never by slot. useitem(330) eats a cake wherever it sits.
  • A bad line does not kill the script. Unknown lines are kept in place and fail only if execution reaches them, and they are listed once at start-up so a real typo is still visible. (One shipped script ends with eighty decorative dashes; it ran for years because end() came first.)

The commands

The command set is the original TextScript v1.6's — 131 names, recovered from the original's own compiled string table rather than guessed from surviving scripts. The authoritative list, each with its argument shape and a comment, is TextScript.java. The shape of the language in one table:

KindExamples
Doing thingswalkto(x,y) attacknpcbyid(id) atobjectbyid(id) useitem(id) useitemwithitem(id,id) pickupitembyid(id) dropitem(id) wearitem(id) talktonpc(id) thievenpc(id) castonnpc(spell,id) buyitem(id,n) sellitem(id,n) deposit(id,n) withdraw(id,n) prayeron(n) setfightmode(n)
Waiting & flowwait(ms) goto([label]) end() logout() autologin(true)
Conditions (53 of them)gotoifcountinvover([label],id,n) gotoifatcoords([label],x,y) gotoifincombat([label]) gotoifinvfull([label]) gotoifnpcnear([label],id) gotoifcurstatunder([label],$mining$,n) gotoiflastservermsg([label],text) …
Variables & inputsetvar(#name#,value) setvarbyarg(#name#,n) setvarbygetinput(#name#,prompt)
Talking to youdisplay(text) sysmsg(text) showmessage(text) takepic()
Historical spelling is honoured. Two names are aliases because the original shipped both spellings in one release (gotoifitemcountinvis / gotoifcountinvitemis), and exactly one name was added: gotoifnotsleeping, because everybody typed it by accident for gotoifnotisleeping. Both work. Common alternate spellings like defense/defence and magic/mage are accepted for skill values.

Worked example

A coal miner that banks — the shape of nearly every gathering script:

| Coal.txt -- mine coal at the rocks, bank when full
[mine]
atobjectbyid(110)                    | 110 = coal rock
wait(2000)
gotoifinvfull([gobank])
goto([mine])

[gobank]
walkto(220,634)                      | into the bank
talktonpc(95)                        | 95 = banker
wait(1500)
answer(0)                            | "I'd like to access my bank account"
wait(1500)
deposit(155,100)                     | 155 = coal, all of it
closebank()
goto([mine])
