APOS scripts

APOS was a separate, later bot with an API unrelated to STS's. This tier exists so scripts written for it run untouched — sixteen survive in scripts/APOS/ and all sixteen run. It is a complete, maintained surface, but if you are writing something new, write STS; this page is mostly for reading and fixing the scripts people still have.

The shape — the client owns the loop

The difference that matters: an APOS script never loops and never sleeps. It answers main() with how many milliseconds to be left alone, and the client calls it again after that long. This is a real, complete script:

public class TPM_Position extends Script {
    public TPM_Position(Extension e) { super(e); }

    public void init(String params) { }

    public int main() {
        return random(1, 500);
    }

    public void paint() {
        drawString("Position: " + getX() + "," + getY(),
                   115, 40, 1, 0xFFFFFF);
    }
}
  • init(String params) — once, at /start Name(params).
  • int main() — do one step of work, return the delay in ms before the next call. Returning quickly and often is the idiom; sleeping inside main() is wrong in APOS and stays wrong here.
  • paint() — draw your overlay with drawString(); font and colour per line.

Naming is APOS's lowerCamelCase (getX(), isBanking(), useItemOnObject()) against STS's PascalCase. They are different APIs that happen to share a client; no attempt is made to unify them.

What is under it

Script.java is the framework: 114 methods — the 88 the surviving corpus calls, plus the overloads and pairs that go with them — mapped onto the native Methods layer, each carrying its own comment. Nothing in Script is final, because two surviving scripts override talkToNpc() and useOnNpc() and call super from inside.

Two classes exist under com/aposbot/ because ten of the sixteen scripts import them by name to build an AWT settings window: Constants.ICONS and StandardCloseHandler. Nothing was copied from APOS to write them.

The four honest gaps

All four are things this client lacks, not things APOS did wrong — scripts that use them load and run, they just see the documented answer:

onChatMessage(msg, name, mod, admin)the two booleans meant "sender is a moderator / administrator" and arrive false — the client is not told.
autohop()stored, never acted on. Nothing here hops worlds by itself.
isSleeping()always false; useSleepingBag() still uses the bag. There is no sleep screen.
onTradeRequest()recovered from the server message "name wishes to trade with you" — there is no trade-request packet to hook.
One documented contradiction, resolved in the script's favour: APOS documented useItemOnObject()'s first argument as an inventory slot, but both surviving call sites pass an item id. Both readings are accepted — slot first.
