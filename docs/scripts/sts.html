STS scripts

The native tier. Your script extends Methods, writes a MainBody(), and owns its own loop — the client gives you around 260 PascalCase methods covering everything a player can do and everything a player can see. The API is SkullTorchaScriptable's, recovered from the STS203C release and implemented natively in this client.

Quick start

Save this as scripts/STS/Chopper.java, then type /start Chopper in game:

public class Chopper extends Methods
{
   public Chopper(mudclient mc) { super(mc); }

   public void MainBody(String args[])
   {
      Display("@gre@Chopper started");
      while (Running())
      {
         if (CountInv(14) > 25)          // 14 = logs
         {
            DropItem(14);
            Wait(600);
            continue;
         }
         int[] tree = GetObjectById(new int[]{0, 1});   // 0,1 = trees
         if (tree[0] != -1)
            AtObject(tree[1], tree[2]);   // chop it
         Wait(1000 + Rand(500));
      }
   }
}

No package line, no imports — the client prepends import org.rscdaemon.client.*; when it compiles the file. Edit and /reload; there is no build step.

The shape

  • MainBody(String[] args) is your program. /start Chopper(yew,bank) arrives as args = {"yew","bank"}.
  • Loop on Running() and call Wait(ms) inside the loop. Running() flips false when the player types /stop — a loop that ignores it cannot be stopped politely.
  • Everything is by item/npc/object id, not screen position. Ids are the world's own definition ids — the same numbers the server uses.
  • When MainBody returns, the script is done.

Talking to the player

Display(text)a line in the chat box. Colour codes work: @red@, @gre@, @ran@…
GetOption(question, String[] options)pops a pick-one menu over the game, returns the chosen index — how a script asks "which alchemy?" before starting work
GetInput(prompt)asks for a typed line
ToShow(Stats)puts your own text overlay on screen — see any shipped script's status display
OnInput(line)override to receive unrecognised / lines while running — your script's own commands

Events you can override

OnChatMessage, OnPrivateMessage, OnServerMessage, KeyPressed, OnInput — override the ones you want; the defaults do nothing.

Gotchas

  • The finders return arrays, and the first slot differs on purpose: object, wall-object and ground-item finders answer [id, x, y]; the npc finders answer [index, x, y]. Either way -1 in slot 0 means nothing matched — check it before using the coordinates. The asymmetry is STS's own and 2006-era scripts depend on it.
  • Wait() generously. The game ticks at 50/s but the server acts far slower; a tight loop with no wait just burns CPU and looks like a machine. Every surviving human-written script waits 300–2000 ms with a random jitter.
  • IRC methods exist and answer honestly: UsingIRC() is false and the Irc* calls are inert — STS's IRC integration has no server to talk to any more, but scripts that call it still load.
