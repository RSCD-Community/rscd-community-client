SBoT scripts

SBoT was RichyT's bot — not related to STS, TextScript or APOS, with its own script shape: a script declares the chat commands it answers to, and is handed whichever one the player typed. Scripts go in scripts/SBoT/.

The shape

public class Test extends Script
{
    public Test(mudclient rs) { super(rs); }

    public String[] getCommands()
    {
        return new String[]{"test"};
    }

    public void start(String command, String[] param)
    {
        while (Running())
        {
            DisplayMessage("Test", 3);
            Wait(2000);
        }
    }
}
  • getCommands() — the names this script answers to. One class can serve several commands and branch on which arrived.
  • start(command, params) — the script body; /start test(a,b) arrives as command="test", param={"a","b"}. Loop on Running(), wait with Wait(ms), exactly like STS.
  • Inside the class, Script means the SBoT base — the loader stages it so the historical extends Script line compiles unchanged in this folder.

The API — SBoT's names and STS's, both

SBoT's API is a renaming of a subset of STS's. Reines shipped an SBoT emulator with STS — a table mapping about 170 SBoT method names onto STS ones — and that mapping is ported faithfully in SBotScript.java, including the deprecated stubs: a script that calls PlayerAt() gets his "deprecated" message, not a compile error. Because the base extends Methods, everything on the STS surface works in an SBoT script too — both names are live.

Reines's own warning still applies, argument order on one call differs between the two worlds: 
SBoT:  UseOnObject(int x, int y, int item)
here:  UseOnObject(int item, int x, int y)

Why the host is new even though the API is old

The original SBoT host could not be ported: it stopped scripts with Thread.stop() (throws on JDK 20+), found them with Class.forName() (classpath only, not a folder), and looked in whatever directory the file manager happened to be in. ScriptRunner does that job the same way it does for the other tiers — compiles the folder, loads through its own class loader, stops cooperatively via Running().
